# ひかりボード（仮称・家庭教師アプリ） 全体の方針と段階 1 の設計書

日付: 2026-11-21（同日に方針を改めて書き直し）
対象: 要件定義書 v0.1（`中学生向けAI理科学習アプリ_要件定義書_v0.1.md`）

この文書は、作る人が要件定義書とこの文書だけを読んで計画を立てられるように書いたもの。
「決めたこと」はそのまま作る。「暫定」の数値は `js/config.js` にまとめる。「作る人に任せる」は作る人が決めてよい。

## 1. 何のために作るか

授業や家庭学習でつまずく中学生が、自分から質問・実験・確認を繰り返して理解を深められるようにする（要件定義書 3 章）。
このアプリの中心は 2 つ。

1. 光源・鏡・レンズを指で動かせる**ホワイトボード（盤）**
2. その盤に図を出しながら個別に教える **AI との対話**

最初の試作は中 1「光の世界」の全範囲（直進・反射・屈折・全反射・凸レンズ・実像と虚像）。

## 2. 全体の方針（2026-11-21 ユーザー決定）

### 2.1 ほかのアプリとの関係

- 家庭教師アプリは、理科クエストにも授業ログにも**組みこまず、別のアプリのまま**にする。両方から開けるようにつなぐ。
- **ログインは授業ログの生徒 ID を使う**（理科クエストと同じ仕組み）。
- **最初の入口は理科クエストに置く**。問題や解説の画面から、今の単元と問題を渡して開く。**次に授業ログにも入口を置く**。
- 解説カード・確認問題・理解度・経験値は理科クエストが既に持っているので、**こちらでは作らない**。こちらは盤と AI の対話に集中する。

理由: AI は無料枠の上限や通信の失敗で止まりやすい。別のアプリにしておけば、止まっても理科クエストと授業ログの本体に影響しない。授業ログの規則（159 項目の確認）に AI の会話を混ぜないためでもある。

### 2.2 段階分け

要件定義書 7 章の順を、上の方針に合わせて入れかえた（ユーザー決定）。機能を削るのではなく、順に足す。1 段階ごとに公開まで進める。

| 段階 | 内容 | 必要な外の準備 |
|---|---|---|
| **1（この文書）** | 6 種類の動かせる盤と計算エンジン、実験室、オフライン、盤を直接開く入口（URL） | GitHub の空のリポジトリ |
| 2 | AI。まず無料枠で 30〜40 人が使えるかを試し、そのあと、AI が盤に図を出しながら文字で対話する部分を作る。AI が使えないときは盤だけで使える | AI の鍵と、鍵を隠す中継の置き場所（先生のアカウントで用意） |
| 3 | 授業ログの生徒 ID でのログイン、理科クエストからの入口（単元と問題を渡す）、学習履歴の同期と PDF 保存 | 授業ログの Firebase の規則の追加、理科クエスト側の入口 |
| 4 | 音声と写真による質問、読み上げ | 段階 2 |
| 5 | 授業ログからの入口、授業モード（先生操作・画面連動）、先生用機能（学習状況の要約、教材） | 段階 3 |
| 6 | iPad での実地テスト、ほかの単元 | |

段階 2 以降は、その段階の前に設計書を別に書く。

### 2.3 要件定義書とのちがい

- 要件定義書の「確認済みの図を使った解説」「確認問題」「理解状況に応じたヒント」は、段階 1 では作らない。理科クエストの教材と、段階 2 の AI の対話で受け持つ。
- 要件定義書の「自由学習・AI おまかせ学習の切り替え」は、段階 2 で AI と一緒に設計する。段階 1 は自由にさわる実験室だけ。

## 3. 段階 1 のゴール・やらないこと・失敗の条件

### ゴール

1. 6 種類の盤を、iPad の指で無理なく操作できる。
2. 動かしたとおりに、光線・角度・像が法則どおりに変わる。
3. 各盤に、先生（キューブ先生）の短い案内と「ためしてみよう」がある。
4. 一度開けば、通信なしで全部使える。
5. 通信と AI の状態が画面で分かる。
6. URL で盤を指定して直接開ける（あとで理科クエストから開くため）。
7. 盤の配置データ（シーン）を、段階 2 で AI がそのまま出せる形にしておく。

### やらないこと（段階 1）

- AI との対話、音声・写真、読み上げ（段階 2・4）
- ログイン、学習履歴、同期、PDF（段階 3）
- 解説の教材、確認問題、理解度、おまかせ学習（2.1・2.3）
- 授業モード、先生用機能（段階 5）
- 端末への保存（段階 1 では何も保存しない。開き直すと、盤ははじめの配置に戻る）

### 失敗の条件（できていても失敗とみなす）

- 法則に合わない光線や像が 1 つでも描かれる。
- 指でつかめない部品、ホバー前提の操作。
- AI が使えるかのように見える表示（段階 1 では AI は動かない）。
- 教科書の本文や図の転載。文章と図は自作する。

## 4. 制約

- 外部ライブラリなし（HTML・CSS・JavaScript だけ）。インストール不要。`npm test` は Node.js の標準のテスト機能だけを使う。
- iPad（Safari・Chrome、タッチ）を優先。スマートフォン（幅 375px）とパソコンでも崩れない。
- 外部への送信なし。名前を入れる欄は作らない。
- 公開は GitHub Pages（運用費 0 円）。
- 編集するのは `家庭教師アプリ` フォルダの中だけ。理科クエストのものはコピーして持つ（別のリポジトリになるため）。

## 5. 作り方の案と、選んだもの

| 案 | 内容 | 判断 |
|---|---|---|

## 6. 利用者から見た動き（決めたこと）

### 6.1 見た目

モックアップ第 3 案 `docs/mockups/stage1-mockup-rika.html` に合わせる（ユーザーの承認まち。第 2 案 `stage1-mockup.html` は全体を AhaBoard 風にした比較用）。

- **枠は理科クエストに合わせる**: うすい青の背景（`#EEF3FF`）、白い角丸カード、青（`#1A5CFF`）、ふつうのゴシック体。理科クエストから行き来しても、別のアプリに見えないようにする。
- **盤の中だけホワイトボード風**（AhaBoard を参考）: クリーム色の紙に点の方眼、手描き風の線、手書き風の書きこみ。AhaBoard の名前・ロゴ・絵・文章は使わない。
- ボタンの枠は目立たせない（ユーザー指示）。押せることは、うすい青の塗りと太字で示す。選んでいるものは青の塗り。
- 先生は理科クエストのキューブ先生（`mascot_E.svg`）（ユーザー指示）。
- 盤の手書き風の文字は、端末に入っている教科書体・丸ゴシックを使う（暫定。Claude の判断）。

**目に優しく、見やすくする決まり**（ユーザー指示。Codex の評価 `.ai-review/20261121-211022_mockup-design_round1.md` を受けて決めた）:

- 文字と背景のコントラスト比は 4.5:1 以上、盤の線と操作部品は 3:1 以上。盤の色は、光線 `#B45C00`、青のペン `#176AA3`、赤のペン `#B23A36`、法線 `#67748B`、緑 `#216E43`、紙 `#FAF7EE`。
- 盤の中の文字は、盤が縮んでも実表示で説明 16px 以上、角度の数字 19px 以上を保つ（盤の表示幅から計算する）。パネルの案内・課題・操作の文字は 16px 以上。
- 盤の線の太さは、盤が縮んでも画面上で一定に保つ（光線 4px 前後、法線 2.5px 前後）。手描き風のゆらぎは弱くする。
- 色だけで区別しない。角度には名前（入射角・反射角）、光線には向きの矢印、できたものには ✓ を付ける。
- 角度の数字と名前は、角がせまいとき（0° 付近）も互いに重ならない位置に置く。
- 今の値（例: 入射角 40° ＝ 反射角 40°）と操作の説明は、盤の中ではなく盤のすぐ下の行に出す（盤の中の文字と重ならないようにするため）。盤の表示幅が 360px 未満のときは、盤の中には角度の数字だけを出し、名前は下の行に任せる。
- 盤の中の固定の文字（法線・鏡など）とつまみも、同じように表示幅から大きさを計算する。6 種類の盤すべてに当てはめる。

**実装で決めたこと**（2026-11-21〜22。モックアップとのちがいを含む）:

- 盤の見出しは、盤の中ではなく、盤のすぐ上の行に出す（盤の中に置くと光源や鏡に重なるため。モックアップでは盤の中の左上だった）。
- 盤の中の文字は、ほかの文字・つまみ・面や軸の線（鏡・水面・法線・光軸・スクリーン・ついたて・レンズの中心の線）と重ならない場所に自動で置き、紙の色のふち取りを付ける。置き場のない文字は、その幅では出さない。角度の数字だけは必ず出す。
- 盤の下の行の値は、角度（°）と「〜倍」だけを数で出す（例: 「物体の位置 焦点距離の 2.0 倍」「像の大きさ 物体の 1.0 倍」）。盤の座標の数は出さない。
- 実像と虚像の盤では、レンズの外に当たる代表の光線は描かない（光がレンズのない所で曲がる図にしないため）。「平行 → 焦点」と「中心を直進」の 2 本は必ず残る。
- 角度が 0.5° 未満のときは 0° として扱い、2 つの数字を法線の左右に分けて置く。
- 動かせる部品には見えるつまみを付け、つかむ範囲は実表示で半径 24px 以上を保つ。
- 幅 900px 以下では 1 列（盤が上、パネルが下）にする。
- 使えないもの（「先生への質問は準備中です」）は、灰色の地と文で、押せるものと区別する。

### 6.2 画面

| 画面 | 役割 |
|---|---|
| ホーム | 見出し、6 種類の盤の一覧（問いかけの形）、通信と AI の状態 |
| 盤 | 中央に盤。横にパネル（先生の短い案内、「ためしてみよう」、今の値、切り替え、「はじめの配置にもどす」、押せない「先生に質問する（AI は準備中）」） |

配置: 幅が 900px より広い画面（横向きの iPad・パソコン）は、盤が左（幅の約 64%）、パネルが右。それ以下（縦向きの iPad・スマートフォン）は、盤が上、パネルが下。

### 6.3 6 種類の盤

| 種類（id） | 動かせるもの・切り替え | 表示されるもの |
|---|---|---|
| 直進（`straight`） | 光源、ついたて | 光線、スクリーンにできる影（光が届く範囲と届かない範囲） |
| 反射（`reflect`） | 光源（光の向き）、鏡の傾き | 入射光・反射光・法線、入射角と反射角 |
| 鏡の像（`mirror-image`） | 物体、見る人 | 物体から目に届く光の道すじ、鏡の奥の像（破線の延長） |
| 屈折・全反射（`refract`） | 光源（入射角）、進む向き（空気→水 / 水→空気）、物質（水・ガラス） | 入射光・屈折光・反射光、入射角と屈折角。水→空気で入射角が大きいと屈折光が消えて「全反射」 |
| 凸レンズ（`lens`） | 光源の高さ、焦点距離 | 光軸に平行な光が焦点に集まるようす、焦点 |
| 実像と虚像（`lens-image`） | 物体の位置、スクリーンの位置 | 3 本の代表の光線、像（位置・向き・大きさ）、実像か虚像か、スクリーンにはっきり映るか |

- 角度の表示は整数の度（四捨五入）。
- 屈折率は暫定で空気 1.00、水 1.33、ガラス 1.50。数値そのものは生徒に見せない。
- 部品をつかむ範囲は、見た目より広く取る（暫定: 半径 24px 以上）。

### 6.4 先生の案内と「ためしてみよう」

- 盤ごとに、先生の短い案内（1〜2 文）と「ためしてみよう」（2〜3 個。例: 「入射角を 60° にしてみよう」「空気に出ていく光が消える所をさがそう」）を出す。
- 条件を満たすと、その項目に「できた ✓」が付く。採点や記録はしない。開き直すと消える。
- 文は Claude Code が書く。理科としての正しさは、授業で使う前に先生が確かめる。確認用の一覧を `docs/reports/boards.md` に作る。

### 6.5 状態の表示

- 通信: 「オンライン」「オフライン（このまま使えます）」
- AI: 段階 1 では常に「AI は準備中」。「先生に質問する」の欄は点線で置き、押せない。

### 6.6 盤を直接開く入口

- `?board=<id>` を付けた URL で、その盤を直接開く（例: `…/?board=reflect`）。
- 段階 3 で理科クエストから単元と問題を渡すときは、この形を広げる。

## 7. 端の場合（決めたこと）

| 場合 | 扱い | 画面での見せ方 |
|---|---|---|
| 部品を盤の外や、動かせる範囲の外へ引く | 範囲の端で止める | 部品が端で止まる |
| 光源を鏡・境界の反対側へ引く | 元の側の端で止める | 同上 |
| 2 本の指で同時にさわる | 最初の指だけを追う | 2 本目は無視 |
| 入射角 0°（面に垂直） | 反射は来た道を戻る。屈折は曲がらず直進 | 角度は「0°」 |
| 入射角がちょうど臨界角 | 臨界角以上を全反射とする（誤差の許容 1e-9） | 「全反射」の書きこみ。屈折光は描かない |
| 物体が焦点の上（距離の差が暫定 1px 未満） | 像はできない | 「像はできません（レンズを出た光が平行になります）」 |
| 物体が焦点の内側 | 虚像 | 光線の延長を破線で描き、「虚像（スクリーンには映りません）」 |
| 像が盤の外にできる | 計算はする。描ける所まで光線を描く | 盤の端に矢印と「像はこの先にできます」 |
| シーンのデータが不正（型のちがう値、数字の文字列、空、NaN・無限大、範囲外、知らない部品、id の重複） | 検査で止め、盤を描かない。数字の文字列も不正とする（自動で直さない） | 「この図は表示できません」と理由 |
| `?board=` の値が不正（知らない id、空、とても長い文字、2 つ以上の指定） | 盤は開かず、ホームを出す。2 つ以上あるときも不正とする | ホームの上に「指定された盤が見つかりませんでした」 |
| 「ためしてみよう」の境界の値 | 目標から暫定 ±2°・±6px 以内を「できた」とする。一度「できた」になったら、動かしても消さない | 「できた ✓」 |
| 「はじめの配置にもどす」 | 部品の配置と切り替えを戻す。「できた ✓」は残す | すぐ戻る |

## 8. 中のつくり

### 8.1 ファイル

```
index.html  css/app.css  sw.js  manifest.webmanifest
assets/mascots/mascot_E.svg   キューブ先生（理科クエストからコピー）
js/config.js      暫定の数値
js/geometry.js    角度・交点（理科クエストからコピー）
js/optics.js      反射・屈折・全反射・レンズの計算（画面に依存しない）
js/scene.js       シーンの検査と、光線・像を求める trace
js/boards.js      6 種類の盤のはじめの配置、案内の文、「ためしてみよう」の条件
js/entry.js       ?board= の読み取り
js/board-view.js  SVG に描く、指で動かす
js/app.js         画面の切り替え、状態の表示
tests/*.test.js
tools/            Codex の実装・レビュー、公開用のスクリプト
```

モジュールの形は理科クエストと同じ（ブラウザでは 1 つの名前空間に入れ、Node では `module.exports`）。`board-view.js` と `app.js` 以外は画面なしでテストできるようにする。

### 8.2 シーン

```js
{
  id: 'reflect-basic',
  kind: 'reflect',            // straight | reflect | mirror-image | refract | lens | lens-image
  elements: [
    { id: 'src', type: 'source', x: 120, y: 80, angleDeg: 40, drag: 'rotate' },
    { id: 'm1',  type: 'mirror', x1: 80, y1: 300, x2: 520, y2: 300, drag: 'none' },
  ],
}
```

- `validateScene(scene)` は直す所の一覧（空なら合格）を返す。
- `trace(scene)` は `{ rays: [...線分], angles: [...], images: [...], notes: [...] }` を返す。描くのは `board-view.js` で、`board-view.js` は光の道を自分では決めない。
- 部品の種類と項目の細かい形は作る人に任せる。ただし、段階 2 で AI が JSON として出せる単純な形（数値と短い文字列だけ）にする。

### 8.3 計算

- 反射: 入射角 = 反射角。
- 屈折: n₁ sin θ₁ = n₂ sin θ₂。sin θ₂ が 1 以上なら全反射。
- 凸レンズ: うすいレンズの式 1/a + 1/b = 1/f。倍率 = b/a。a = f は像なし。a < f は虚像。
- レンズの光線は、レンズの中心の面で 1 回だけ曲げて描く（中学の作図と同じ）。

## 9. テスト

- `optics`: 反射角、屈折角（空気→水 30° → 約 22.1°）、臨界角（水 → 約 48.8°）、垂直の入射、レンズ（a = 2f → b = 2f で同じ大きさの倒立、a = 1.5f → b = 3f、a = f → 像なし、a = 0.5f → 虚像で 2 倍）
- `scene`: 7 章の不正なデータをそれぞれ拒む。動かせる範囲の端で止まる。
- `boards`: 6 種類がそろう。はじめの配置が全部検査に合格する。「ためしてみよう」のそれぞれに、条件を満たす配置が実際にある。許容の境界（ちょうど ±2°・±6px）。
- `entry`: 正しい id、知らない id、空、長い文字、2 つ以上の指定。
- `offline`: `index.html` が読むファイルと `sw.js` の一覧が合う。
- 画面はブラウザで確かめる（iPad の幅・スマートフォンの幅・タッチ）。
