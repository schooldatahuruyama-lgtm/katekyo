**おすすめは「開発用PCで音声を事前生成し、MP3として配信する方式」です。音源の第一候補はVOICEVOX Nemo。** 固定台本なら、利用者側の音声合成が不要になり、端末による声の違いもなくせます。

**Nemoを第一候補にする理由は、無料で繰り返し調整でき、独自キャラクターに使いやすく、規約をそろえやすいからです。** ただし「最も自然な声」とは断定しません。聞きやすさが足りなければ、同じ再生方式のままGoogle Cloud製の音声へ差し替えられます。

6体への割り当ては、まず次の組み合わせを試します。すべて「ノーマル」。これは**試聴前の仮案**で、右欄は目指す話し方です。[公式話者・スタイル一覧](https://github.com/VOICEVOX/voicevox_vvm/blob/main/README.md)

| 先生 | Nemoの話者 | 調整の方向 |
|---|---|---|
| まる先生 | 女声1 | 丁寧に、文の区切りを明確に |
| しずく博士 | 女声2 | 少しゆっくり、間を長めに |
| ぷにカプセル | 女声3 | はきはき。速すぎない |
| もくもく先生 | 男声2 | ゆったり、大きな区切りで |
| キューブ先生 | 男声3 | 一定の速さで、用語を明確に |
| まめ博士 | 男声1 | 明るく、発見を喜ぶ調子に |

声の高さを大きく加工するより、別の話者と間の取り方で区別します。最初は話速0.95〜1.0程度から調整し、現在の`pitch`の値は流用しません。

具体的には、次の順で作るとよいです。

1. **まず18本で聞き比べる。**  
   各先生について「普通の説明」「法線・屈折・虚像などの用語」「60°・1本目などの数字」を含む3文を生成。学校のiPadのスピーカーとイヤホンで確認してから、全台本を作ります。

2. **表示用台本と読み上げ用台本を分ける。**  
   JSONに`boardId / stepId / teacherId / text / speechText / voice / settings`を持たせます。表示は「入射角を60°に」、読みは「にゅうしゃかくを、ろくじゅうどに」。`1本目→いっぽんめ`、`凸レンズ→とつレンズ`などを確認し、用語の読み・アクセントを辞書登録します。数字は単位や助数詞とセットで直します。

3. **Windowsで一括生成する。**  
   Nemoエンジンを起動し、Node.jsまたはPythonから  
   `GET /speakers → POST /audio_query → 読み・話速を調整 → POST /synthesis → WAV`  
   と処理します。`speaker`には話者名ではなく、取得した**スタイルID**を渡します。辞書・調整済みデータ・エンジンの版を残し、台本や設定が変わった分だけ再生成します。[公式API手順](https://github.com/VOICEVOX/voicevox_engine#http-リクエストで音声合成するサンプルコード)

4. **配信用はMP3・モノラル・24kHz・64kbpsを出発点にする。**  
   FFmpeg等を開発用PCだけで使い、音量をそろえて変換。圧縮音が気になる場合は96kbpsに上げます。WAVは編集用原本として保管します。MP3はSafariを含む主要ブラウザが対応しています。[形式の対応状況](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs#mp3_mpeg-1_audio_layer_iii)  
   名前は例として`audio/v1/cube/reflection/step-03.<内容ハッシュ>.mp3`。対応表にファイル名・実時間・描画の開始／終了時刻を記録します。

5. **音声の再生時刻に描画を合わせる。**  
   1手1ファイルとし、使い回す1個の`<audio>`で再生。`requestAnimationFrame`から`audio.currentTime`を見て線を伸ばします。例えば「法線」と話す時刻にラベルを出し、**音声終了と描画完了の両方を待って次へ**進みます。時刻は圧縮後の音声で確認します。  
   一時停止は両方停止。「次へ・戻る・先生変更」では旧再生を止め、古い終了イベントを無効にします。読み込み失敗時は再試行・文字だけで続ける選択を出します。

6. **iPadでは準備後に「音声ありで始める」を押してもらう。**  
   最初の音声を準備してからボタンを有効にし、クリック処理内で直接`audio.play()`を呼びます。そこで通信を待ってから再生する形は避けます。以後も同じ要素を使い、`play()`が拒否されたら再開ボタンを表示。画面ロック・別タブ移動では説明を止め、復帰後に再開させます。最初のタップで以後の再生が必ず許可されるとは扱いません。[再生制限への対応](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

7. **音声を専用キャッシュに保存する。**  
   「選んだ先生の音声を保存」「全先生を保存」を用意し、対象ファイルをService WorkerのCache Storageへ保存。全件確認後に「オフライン準備完了」と表示します。再生は**ファイル全体を`fetch`→Blob URL→`audio.src`**とすれば、音声の部分取得（Range）をSW側で扱う複雑さを避けられます。URLは使用後に解放します。  
   保存データは容量不足などで削除され得るため、授業前の保存確認と再ダウンロードを用意します。[保存データの削除条件](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

**利用条件は、コードと音声を分けて管理します。**

- **Nemoの教育・商用・非商用利用：** クレジット付きで利用可能です。アプリの「音声・権利表記」とリポジトリのREADMEに、例えば`音声合成：VOICEVOX Nemo（使用話者：女声1・2・3、男声1・2・3）`と掲載します。[公式規約・表記](https://github.com/VOICEVOX/voicevox_resource/blob/main/voicevox_nemo/engine/README.md)
- **公開リポジトリへの収録：** 音声の利用・他者への許諾を認める規定から、**規約を引き継いで収録できると判断します**。ただし「GitHub公開」を名指しした許可ではありません。音声フォルダにも条件と規約URLを置き、コードのMIT等を音声に一括適用しない設計にします。
- **Nemoで禁止されること：** 無クレジット、著作情報の偽装、権利侵害、信用を著しく損なう利用、生成音声の機械学習利用など。学校利用でも免除されません。[Nemo音声規約](https://voicevox.hiroshiba.jp/nemo/term/)
- **通常のVOICEVOX：** Nemoの条件は流用できません。採用話者ごとに、独自キャラクターへの声当て・音声素材の配布条件を確認します。[ソフトウェア規約](https://voicevox.hiroshiba.jp/term/)
- **Google Cloud：** 生成音声をアプリで使えることは公式に明記されています。今回の約5,800〜14,500文字は無料枠内ですが、超過すると自動課金されます。**音声単体を公開リポジトリで第三者に再利用させる条件と、クレジット義務の詳細は今回確認不足**です。[アプリ利用の説明](https://docs.cloud.google.com/text-to-speech/docs/basics)

弱点は、**台本変更ごとに音声とタイミングの再確認が必要なこと**、初回ダウンロード、合成音声らしさが残ることです。Nemoが聞き取りづらければ、まず読み・アクセント・間を修正し、それでも不足する場合にGoogle Cloud音声を比較します。

現方式を残すなら、[見本の「最初の日本語音声を選ぶ処理」](C:/Users/yan12/Documents/keita/AI開発/家庭教師アプリ/docs/mockups/whiteboard-animation-mockup.html:293)を、音声一覧の更新待ちと試聴・選択に変える余地があります。ただし、6声の統一や音質は保証できません。また、`speechSynthesis`には通信を使う音声もあります。[ローカル／リモート音声の違い](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)

将来のAI自由文は、当面は**文字表示＋希望時の端末読み上げ**が現実的です。同じNemoの声をその場で出すには別の合成環境が必要です。高品質を優先する段階で、設計済みの中継サーバーにTTS・利用上限・音声キャッシュを追加する案が有力ですが、継続的な0円は保証できません。固定説明の音声は、その段階でも事前生成のまま使えます。
